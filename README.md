# Fulfillment Policy Lab

**A policy can look better offline because the logging policy gave it an easier sample. I built this lab to make that failure visible before an incentive policy reaches a trial.**

The decision is narrow: which shopper offer should a fictional grocery marketplace show for an order? The outcome is completion minus a fixed, normalized incentive cost. Only the chosen offer's outcome is observed. A conventional supervised comparison of completed orders by offer confuses context, exploration rates, and policy quality.

This is an original, independently built portfolio experiment using **9,600 synthetic offers across 240 zone-days**. It demonstrates evaluation methods. It contains no employer, customer, or Instacart data and does not substantiate historical workplace results.

## My approach

I treated support as a contract before treating uplift as a number:

1. **Record the decision.** Preserve the full randomized logging distribution, selected action, context, outcome, and zone-day identifier.
2. **Refuse unsupported comparisons.** Check every target context/action pair for zero support and excessive importance ratios, then require effective sample size. Do not silently discard unsupported rows.
3. **Separate selection from evaluation.** Use four group-disjoint reward-model folds on validation data to select one of five predefined policies. Freeze the selection before evaluating the later test period.
4. **Show competing estimators.** Report IPS, self-normalized IPS, clipped IPS, and doubly robust estimates with paired cluster uncertainty. Keep simulator oracle values isolated as diagnostics.
5. **Recommend a trial, not a launch.** State what the simulated result cannot answer, including interference, carryover, and distribution change.

The actual reward model is scikit-learn's `HistGradientBoostingRegressor`. Its input is six decision-time context fields plus action encoding. Oracle expected rewards never enter model fitting or policy selection.

## What the experiment found

The validation stage selected **`modest_offer`**. The test stage used 2,400 offers in 60 unseen zone-days.

| Test result for the frozen policy | Measured value |
|---|---:|
| Doubly robust utility | 0.6554 |
| 95% zone-day cluster interval | [0.6129, 0.6967] |
| Paired DR difference versus no incentive | +0.1533 |
| 95% paired difference interval | [+0.1071, +0.1946] |
| Effective sample size | 749.6 |
| Matching logged offers | 837 / 2,400 |
| Maximum possible importance ratio | 4.348 |

These are **arbitrary utility units**, not revenue, dollars, completion-rate points, or a measured business lift.

The result also exposes two failures worth retaining:

- **Validation selection missed the simulator's best predefined policy.** `high_offer` has higher expected test utility in the isolated oracle diagnostic (0.7056 versus 0.6718 for the selected policy). I kept the frozen selection rather than promoting the winner after seeing test data. One validation period is not a guarantee of optimality.
- **Clipping can move the answer substantially.** For `high_offer`, test IPS is 0.5657 and clipped IPS is 0.3804 at a weight cap of 5; DR is 0.6960. Clipping trades variance for bias. It is not an automatic correction.

The intentionally unsupported `premium` policy assigns probability to an offer the logger never explored. The evaluator returns **no estimate**, with a specific refusal reason.

## Run it locally

Python 3.11, CPU only. No API keys, paid services, cloud account, or GPU.

```bash
python -m venv .venv
# Activate .venv for your shell, then:
python -m pip install -r requirements.txt
python scripts/verify_artifacts.py
python -m unittest discover -s tests -v
python scripts/run.py
```

For stable runtimes, set `OMP_NUM_THREADS=1` and `OPENBLAS_NUM_THREADS=1` in the invoking shell. `scripts/run.py` deterministically regenerates the synthetic log, fits five nuisance models, selects the policy, evaluates test data, and refreshes the artifact manifest. It completes locally without external calls. Small floating-point differences across platforms are possible.

## Limits and next decision

The synthetic logger is randomized and its propensities are known. Real logs require verified randomization or a defensible identification argument. There is no interference, shopper capacity coupling, incentive carryover, or adaptive logging here. The six-feature environment is stationary; the temporal split does not prove robustness under drift. The bootstrap assumes independent zone-days and holds nuisance fits fixed. Intervals for the five descriptive policy estimates are not simultaneous confidence bands.

The next step would be a prospectively designed, adequately powered randomized marketplace trial with spillover boundaries, guardrails, and a predeclared analysis plan. This repository does not run such a trial.
